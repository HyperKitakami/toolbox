颜色混合

给两个颜色，算出它们叠在一起是什么样。可以用正片叠底、滤色、叠加等 16 种混合模式 得到唯一的结果色，也可以在两者之间铺出一整条过渡色阶。

混合模式算的是什么

按 W3C《Compositing and Blending Level 1》里的混合函数实现，取值与 CSS 的 mix-blend-mode 一致，所以在浏览器里看到的叠加效果和这里算出来的一样。

  • 可分离模式（正片叠底、滤色、叠加、变暗、变亮、颜色减淡、颜色加深、强光、柔光、差值、排除） 逐通道独立计算，红管红、绿管绿。
  • 不可分离模式（色相、饱和度、颜色、明度）要动色相与饱和度，必须三个通道一起算， 先用明度或饱和度做整体平移，再把溢出的分量按比例压回来。
  • 只处理不透明颜色，不做透明度合成 —— 混合模式与透明度叠加是两件事， 混在一起算容易得到难以解释的结果。

底色和叠色是分方向的

叠加（overlay）与强光（hard-light）是一对换位版本：overlay(底色, 叠色) 等于 hard-light(叠色, 底色)。交换两个颜色，结果通常不一样， 所以界面上把「底色」放在左边、「叠色」放在右边，随时可以交换过来比。

另外几个模式是可交换的：正片叠底、滤色、变暗、变亮、差值、排除， 谁上谁下结果相同。

RGB 与 HSL 两种过渡

  • RGB：三个通道各自线性插值。路径直，但两种差异大的颜色之间容易经过发灰的中间色。
  • HSL：色相、饱和度、明度各自插值，色相走最短的那一边（相差超过 180° 就绕近路）， 过渡时色相更稳定，做渐变更自然。
  • 灰色没有色相可言，如果直接拿 hsl() 里的 0 去插值， 灰到红的过渡会莫名其妙地绕经青绿色。这里让无彩色借用另一端的色相，避免这条错误路径。
  • 色值按整数显示，把显示出来的值粘回去可能有 ±1 的偏差，属取整的正常范围。
