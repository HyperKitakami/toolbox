测试数据生成

批量生成中文姓名、手机号、邮箱、地址这类假数据，用来填测试库、造演示数据或做表单联调。 邮箱用 RFC 保留域名、IP 用保留文档段、身份证号用省级地址码 —— 生成的东西不会落到真人身上。可导出 CSV 或 JSON。

为什么这些字段是安全的

  • 邮箱域名只用 example.com / example.net / example.org （RFC 2606 保留）与 .test（RFC 6761 保留）。 这几个域名永远不会指向真实的收件人，误发也发不出去。
  • IP 地址只用 192.0.2.x / 198.51.100.x / 203.0.113.x —— RFC 5737 专门留给文档与测试的三段，不会指向真实主机。
  • 身份证号的地址码用的是省级代码（如 330000），而真实身份证号用的是区县级代码 （330101 这种）。所以生成的号码格式与校验位都正确、 可以拿来测校验逻辑，但不会与真实公民号重合。
  • 手机号这一项没法两全：用假号段格式就不对，用真号段就可能撞上真人。 这里选了后者，并在上面明确警告 —— 测试数据要的就是格式真实。

没有银行卡号，也没有真实区县

  • 不生成银行卡号。卡号有 Luhn 校验位，一旦按规则生成， 就有可能恰好是某个真人的卡号 —— 而卡号的后果比手机号严重得多。 这一项宁可没有。
  • 区县用的是「通用区名」（城关区、新城区、朝阳区、人民路…）， 这些名字在全国很多城市都真实存在，配到哪个市都不违和。 这样就不必维护一份几千条的完整行政区划表，也不会生成「浙江省兰州市」 这种不存在的组合。
  • 省与市是真实的对应关系，覆盖全部 34 个省级行政区。 港澳台按中国的省级行政区列出。

导出的格式

  • CSV —— 逗号分隔，按 RFC 4180 处理引号与换行转义， 行尾用 CRLF。文件开头带 UTF-8 BOM：没有它的话 Excel 会把中文当成 Latin-1 打开，满屏乱码。
  • JSON —— 一个对象数组，键就是中文列名。
  • 「复制 CSV」复制的内容与导出的文件完全一致（含 BOM 与 CRLF）， 可以直接粘进表格软件。

常见用途

  • 填测试库：造一批用户表记录，看分页、排序、搜索在真实数据量下的表现。
  • 做演示：给客户看的原型里填上像样的中文数据，比「测试1 / 测试2」有说服力。
  • 测表单：拿长地址、带连字的公司名去试输入框会不会溢出。
  • 测校验逻辑：身份证号的校验位是按 ISO 7064 MOD 11-2 算的，可以直接喂给校验函数。
