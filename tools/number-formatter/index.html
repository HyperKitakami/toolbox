数字格式化

一个数字，各种写法：千分位分组、自定义小数位、科学 / 工程计数法、百分比、货币与 人民币大写金额。全程按十进制字符串计算 —— 大整数不丢精度，1.005 保留两位也不会变成 1.00。

为什么不用 toFixed / toLocaleString

  • (1.005).toFixed(2) 得到 1.00。 原因是 1.005 在双精度里其实是 1.0049999999999998934，取整时「按二进制的值」四舍五入， 结果就比用户预期少一分。同理 (8.575).toFixed(2) 是 8.57、(2.675).toFixed(2) 是 2.67。
  • 本工具把你的输入当成十进制字符串来算，取整在数字串上做进位， 所以 1.005 保留两位就是 1.01。
  • (1e21).toFixed(2) 返回的是 1e+21 —— 超过 10²¹ 之后 toFixed 直接放弃，小数位设置被无声忽略。
  • toLocaleString 的「千分位」不是一个确定的行为： en-US 给 1,234,567.89、 en-IN 给 12,34,567.89（印度是 3-2-2 分组）、 de-DE 给 1.234.567,89。 这里的分组方式与分隔符由你显式选择，不跟着宿主环境漂。
  • 整数位超过 2⁵³−1（约 9007 万亿）时，浮点数已经存不下这个数了 （Number("12345678901234567890") 会变成 12345678901234567000）。本工具不经过浮点数， 40 位以内的结果都是精确的，界面上也会提示这一点。

千分位与小数分隔符

  • 3 位分组 —— 英语与中文环境最常见：1,234,567.89。
  • 印度式 3-2-2 —— 最后三位一组，往前每两位一组： 12,34,567.89。印度与部分南亚地区用这个写法。
  • 小数分隔符 —— 选 1,23 时， 千分位自动换成 .（1.234.567,89）， 这是德语 / 法语 / 西班牙语等环境的写法。
  • 输入时反过来：逗号只当千分位分隔符，且必须落在合法的分组位置上。 1,5 在德语里是 1.5、在英语里是 15 —— 猜错方向的代价太大， 所以这种写法会直接报错，请改成 1.5。
  • 下划线（1_234_567）与各种空格也会被剥掉， 方便从代码或日志里直接粘。

取整方式

  • 四舍五入（默认）—— 正好一半时远离零： 2.5 → 3、-2.5 → -3。 注意 JavaScript 的 Math.round(-0.5) 得到的是 -0（朝 +∞ 取整），而 (-0.5).toFixed(0) 是 -1 —— 两者并不一致，本工具统一按「远离零」处理。
  • 银行家舍入 —— 正好一半时取到偶数： 2.5 → 2、3.5 → 4。 做财务汇总时用它，可以避免「总是向上进位」带来的系统性偏差。
  • 截断 —— 直接丢掉多余的位，不进位。等价于朝零取整。
  • 三种模式只影响「被丢掉的第一位正好是 5 且后面全是 0」这一种情况； 只要后面还有非零数字，就一律进位（那已经不是正好一半了）。

人民币大写金额的规则

  • 依据《正确填写票据和结算凭证的基本规定》：数字用 壹贰叁肆伍陆柒捌玖，单位用 拾佰仟 与 万 / 亿 节， 10 写作 壹拾 而不是 拾。
  • 连续的零只写一个，节末尾的零不写： 1409 → 壹仟肆佰零玖、 6007 → 陆仟零柒、 1000000 → 壹佰万。
  • 到「元」为止的在元后写「整」，有「分」的不写： 1409.50 → 壹仟肆佰零玖元伍角整； 6007.14 → 陆仟零柒元壹角肆分。
  • 元位是 0 而角位不是 0 时，规范说这个「零」可写可不写 （原文：「可只写一个『零』字，也可不写『零』字」）。本工具统一写： 107000.53 → 壹拾万柒仟元零伍角叁分， 与规定里的示例一致，也更防涂改。
  • 金额先取整到「分」再转大写；负数会加「负」前缀 —— 票据上通常不写负数，这里只是保留符号不至于丢失。
